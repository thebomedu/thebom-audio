## 구현한 테스트 기능

- 대시보드: 재원/출결/확인 대기/미수금과 활동 기록
- 학생: 가상 학생 등록, 중복 4자리 출결번호 방지, 담당 교사, 재원/보관, 메모
- 리딩랩: 교재 배정, 시작 Unit, 요일별 계획, 완료 체크, 교사 최종 확인
- 맞춤 과정: Unit별 과정 > 학생별 과정 > 교재 기본 과정 우선순위
- 기록 보호: 안정된 단계 ID, 완료 기록이 있는 과정 구조 변경 차단, 설명·페이지 수정 허용
- 교재: 등록, 기본/Unit별 단계 편집·복사·복원, 보관, Unit 축소 차단
- 음원: HTTPS URL 또는 1.5MB 이하 테스트 파일 업로드, 학생 화면 재생, Android 클래스카드 앱 실행 링크
- 출결: 4자리 태블릿 입력, 등원·하원, 중복 방지, 사유를 남기는 수동 수정, CSV
- 교사: 가상 교사 등록·수정·보관, 담당 학생, 교사 화면에서 담당 학생만 표시
- 수강료: 월별 청구, 중복 청구 방지, 부분 수납, 과수납 차단, 미납, 미수납 청구 취소, CSV
- 학부모 알림: 초안 저장·편집·검토·복사. **실제 전송 없음**
- 월간 리포트: 선택 월 출결·완료 Unit, 생성 시점 누적 진도, 코멘트·가정 학습, 스냅샷 보존, 인쇄/PDF, 알림 초안
- 서버 저장: 비공개 테스트 사이트의 별도 D1에 ChatGPT 사용자 ID별 저장. 낙관적 버전 검사로 동시 덮어쓰기 차단
- 브라우저 단독 모드: 이 폴더를 정적 제공하면 해당 브라우저에만 저장. 온라인 사이트는 `?cloud=1` 모드로 API를 사용

## 테스트할 흐름

1. 교재·Unit → 리딩랩 → Unit 1과 Unit 2 과정이 다른지 확인합니다.
2. Unit 2 설명/페이지를 수정하고 저장합니다. 학생 화면의 같은 Unit에 반영됩니다.
3. 학생 화면 → 봄이 → Unit 1의 남은 단계를 체크합니다.
4. 원장 화면 → 확인 대기 → 최종 확인합니다. 학생이 확인 완료 Unit을 수정할 수 없습니다.
5. 태블릿 출결 → 1001로 등원·하원합니다. 반복 처리는 차단됩니다.
6. 수강료 → 청구 내역 → 일부 금액을 수납합니다. 잔액과 합계를 확인합니다.
7. 월간 리포트 → 봄이 선택 → 생성합니다. 출결과 완료 Unit이 반영됩니다.
8. 수정·새로고침·동일 계정의 다른 기기에서 열기로 서버 저장을 확인합니다.
9. 테스트 설정 → 초기화로 가상 데이터로 돌아갈 수 있습니다.

## 검증

`node --test tests/*.test.mjs` (저장소 루트, Node 24)

16개 도메인/SQLite API/격리 테스트: 과정 우선순위·기록 보호·완료 승인·진행률·출결 중복·부분 수납·월간 스냅샷·트랜잭션 롤백·학생별 과정·미인증 거부·사용자별 저장 격리·동시 수정 충돌·잘못된 요청 거부.

브라우저 확인: 학생 체크 → 교사 확인, 태블릿 등원·하원, 수납 저장, 리포트 생성, Unit 수정 → 학생 반영. 로컬 HTTP 미리보기에서 발견한 UUID 생성 호환성 오류를 수정했습니다. 온라인 게이트와 배포 성공은 확인했습니다. 인증된 온라인 계정으로 실제 저장/기기 간 왕복은 원장님 첫 접속 검수가 필요합니다.

## 배포 소스

테스트 사이트의 전체 Vinext/Cloudflare 소스는 Sites 전용 소스 저장소에 커밋되어 있습니다. 이 GitHub 경로는 공통 프런트엔드와 서버 동작의 핵심 코드/테스트를 보관합니다. `server/route.example.ts`는 Sites 소스의 실제 API 라우트 사본으로, 경로/인증 헬퍼는 Sites 프로젝트 구조에 맞게 연결해야 합니다. `server/schema.sqlite.sql`은 **독립 테스트 D1 전용**이며 Supabase에서 실행하는 SQL이 아닙니다.
