# 더봄어학원 외부 서비스 연동 준비
작성일: 2026-11-04 (Asia/Seoul)
대상 브랜치: develop/integrated-management
상태: 사전 준비. 외부 계정 연결·계약·템플릿 제출·실제 발송·결제 호출은 미실행.

## 현재 상태
- 독립 테스트 사이트의 학생별 납부방법, 보호자 연락처, 청구일, 미납 잔액, 안내 대상 선택 및 초안 저장 기능을 활용한다.
- 자동 청구 점검은 테스트 장부 생성만 수행한다. 이 작업에 실제 발송이나 결제 API 호출을 추가하지 않는다.
- 운영 홈페이지·학생 데이터베이스와 분리하고, 운영 반영은 원장 승인 후 진행한다.
- 현재 API 키, 결제선생 사업장 식별자, 카카오 발신프로필, 승인 템플릿, 외부 수신 결과는 확인되지 않았다.
- 현재 초안·검토 완료 상태는 실제 발송 완료가 아니다.

## 연결 경로
| 업무 | 연결 서비스 | 실행 기준 |
|---|---|---|
| 결제선생 청구서 안내 | 결제선생 API | 제휴 승인과 Sandbox 테스트 완료 후 청구서 발송 기능 연결 |
| 결제 결과 반영 | 결제선생 결과 조회/통지 | 공식 계약 명세의 결과 검증 방식 확인 후 구현 |
| 현금·계좌이체 수강료 안내 | 카카오 알림톡 대행사 API | 원장이 선택하고 수신자·금액·승인 문구를 확인한 건 |
| 등원·하원 알림 | 카카오 알림톡 대행사 API | 테스트 검증 후 자동 발송 여부를 별도 설정 |
| 월간 학습 리포트 | 카카오 알림톡 대행사 API | 리포트 확정 후 선택 발송. 개인별 접근 제어된 링크 준비 필요 |
| 운영 공지 | 내용에 맞는 메시지 상품 | 정보성 알림과 홍보성 안내를 구분, 제공사 기준 확인 후 처리 |

결제선생 대상은 현금·이체 안내 선택에서 제외한다. 납부방법 미설정 학생을 임의로 분류하지 않는다.
수납 완료·취소·청구일 전·연락처 미등록·비재원은 현재 수강료 초안 대상 조건에 따라 제한한다.
동일 청구의 중복 초안을 막는 현재 기능과 외부 발송 중복 방지는 별도다. 실제 연동 시 발송 요청 ID 및 제공사 결과로 중복을 제어해야 한다.

## 원장에게 필요한 확인 (비밀값 제외)
1. 결제선생 사용 중인지, API 제휴 신청/승인 여부, Sandbox 키 발급 여부.
2. 학원 카카오톡 채널 주소, 비즈니스 채널 전환 여부.
3. 기존 알림톡 발송 대행사명 또는 아직 없음.
API 키·비밀번호는 대화나 학생 화면, GitHub에 넣지 않는다. 제공사가 정해진 뒤 서버 비밀 설정 경로를 안내한다.

## 결제선생 준비
공식 온보딩은 상담 → 제휴 계약 → Sandbox 키 → 연동 검수 → Live 키 절차를 안내한다.
API 제공 여부는 결제선생의 심사 대상이며 이용 계정만으로 승인되었다고 가정하지 않는다.
사업장 연결 방식, 테스트 연락처 제한, 청구 생성/취소, 결제 결과/부분취소, 인증, 재시도 및 호출 제한을 해당 계약 버전에서 확인한다.
Sandbox 키를 받기 전 운영 URL 또는 임의의 API 규격으로 구현하지 않는다.
승인 불가 시 결제선생 기존 관리도구 사용을 유지하고, 자체 장부와 현금·이체 안내 기능은 독립적으로 진행한다.

## 카카오 준비
비즈니스 채널, 발신프로필 등록, 발송 대행사 API 이용, 템플릿 심사 상태를 확인한다.
아래 문구는 심사 준비 초안이며 승인된 템플릿이 아니다. 변수 표기와 버튼 형태는 선정 대행사 규격에 맞춘다.
실패 시 문자 자동 대체는 기본 비활성화한다. 사용 여부·발신번호 등록·비용 확인 후 결정한다.
임의로 수정한 자유 문구를 승인 템플릿인 것처럼 보내지 않는다.

### 현금 수강료 안내 초안
[더봄어학원 수강료 안내]
#{학생명} 학생의 #{청구월} 수강료를 안내드립니다.
납부 금액: #{미납금액}원
납부 방법: 현금
납부 기한: #{납부기한}
이미 납부하신 경우 학원으로 확인 부탁드립니다.
문의: #{학원연락처}

### 계좌이체 안내 초안
[더봄어학원 수강료 안내]
#{학생명} 학생의 #{청구월} 수강료를 안내드립니다.
납부 금액: #{미납금액}원
납부 기한: #{납부기한}

이미 납부하신 경우 학원으로 확인 부탁드립니다.
문의: #{학원연락처}
계좌정보가 확인되기 전에는 이 문구를 실발송하지 않는다.

### 등원/하원 초안 (각각 별도 심사 준비)
[더봄어학원 등원 안내]
#{학생명} 학생이 #{등원일시}에 등원했습니다.
[더봄어학원 하원 안내]
#{학생명} 학생이 #{하원일시}에 하원했습니다.

### 월간 리포트 초안
[더봄어학원 월간 학습 리포트]
#{학생명} 학생의 #{리포트월} 학습 리포트가 준비되었습니다.
아래에서 학습 내용을 확인해 주세요.
버튼 후보: 학습 리포트 확인
리포트 링크는 다른 학생에게 접근할 수 없고 만료·회수가 가능하도록 구현 후 사용한다.

### 운영 공지 초안
[더봄어학원 수업 안내]
#{안내제목}
#{수업관련안내내용}
문의: #{학원연락처}
가변 본문 허용 범위는 제공사 심사 확인이 필요하다. 행사 홍보·모집·할인 문구에 이 초안을 재사용하지 않는다.

## 구현 순서
1. 계정/채널/제공사 확인 및 공식 명세 확정.
2. 서버 전용 Sandbox 설정, 인증된 관리자 API와 제공사별 어댑터 구현.
3. 수신자 허용목록을 원장 테스트 번호로 제한. 가상 학생만 사용.
4. 요청 생성과 발송 상태 분리: 초안 → 확인 → 요청 → 제공사 접수 → 결과.
   접수만으로 성공 처리하지 않으며 응답 불명 상태는 재발송 전 결과 조회.
5. 소유자/실제 교사 권한 검증 추가. 현재 화면 시연 역할을 실권한으로 사용하지 않음.
6. 발송 직전 잔액·취소·연락처·납부방법 재확인, 요청 중복 방지와 결과 재수신 멱등 처리.
7. 결제 결과는 인증된 제공사 결과로만 장부 반영. 금액·청구 ID·사업장 확인.
8. 테스트 결과를 원장에게 보여주고 운영 활성화 승인 후 별도 전환.

## 검증 항목
- 결제선생 대상이 현금/이체 알림과 중복되지 않음.
- 현금/이체 미납금만 안내하고 부분 납부 후 잔액 재검증.
- 연락처 누락·비재원·취소·수납 완료는 차단.
- 중복 클릭, 지연 응답, 타임아웃, 결과 중복/역순 통지에도 중복 발송·수납 없음.
- 다른 학생 리포트와 다른 소유자의 데이터에 접근 불가.
- 테스트 수신자 외 발송 차단. 메시지·인증값을 로그에 그대로 남기지 않음.
- 운영 데이터 변경 없음. 발송 기능 차단 스위치로 즉시 중단 가능.
